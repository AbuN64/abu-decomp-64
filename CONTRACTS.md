# Contracts

The uppercase requirement words MUST, MUST NOT, SHOULD and MAY follow [RFC 2119](https://www.rfc-editor.org/rfc/rfc2119).

## Roles

- **unbake** is the objective framework with the hard rules (setup, score, submit, land, report).
- **Recipe Maker** reads the ROM and sends objective work through unbake; the language model supplies names, purpose and structure.
- **Cake Taste** is the standalone prodder: recomp, repro, probes, traces, handoff packets. It depends on no decomp tool.
- **abu-decomp-64** is the dev cycle and its seat. It depends on all three and acts on them only through their public CLIs and published files.

Project facts (paths, addresses, titles, repositories, ports, lane names) live in profiles and specs, never in this package.

## Modules

| Module | Boundary |
|---|---|
| `cli` | One entry point. Every command prints one envelope `{ok, result, findings, stages, invocation}`; help is plain text and `mcp` speaks MCP on stdout. Commands register in `COMMANDS` with their own argument definitions. |
| `config` | One explicit JSON seat profile. Unknown or missing top-level keys fail with `file:key`. Each component validates its own section: `tools`, `events`, `stream`, `console`, `lanes`, `supervisor`, `build`. |
| `tools` | Pins and passthrough. Pins are this distribution's own direct requirements, read from its installed metadata. `decomp dependencies` requires each tool's `direct_url.json` at the pinned commit, Recipe Maker on the same unbake commit, and Cake Taste free of unbake and Recipe Maker. `decomp --version` prints decomp's and the pinned tools' versions. `decomp unbake|recipe|taste ARGS` runs the tool's `main(argv)` in an isolated interpreter with ARGS untouched (argparse never sees them); a call that starts with an option or contains `--help`/`-h` (`--version`, `score --help`) is answered in the tool's own text and exit code, not a JSON envelope; project, host and Taste profile come from the `tools` section; `decomp unbake|recipe --project DIR [--host FILE] ...` targets another tree (a lane's own) with the same pinned tool and is refused when that tree's pin file (`tools.pin_file`, default `ci/run`, a wheel URL naming the version) pins another version than the one installed. Only the values a call uses are read and checked: a project or host given on the command line replaces the section's value without the section's value being resolved (it may name something that does not exist, or be absent), `tools.checkouts` (optional, tool command -> git checkout the seat runs that tool's code from) is pinned like the packages: every call of that tool fails fast with `tools.checkout_drift` naming the path, its HEAD and the pin when they differ, and `decomp tools deploy` fetches and detaches the checkout at the pin, refusing (`deploy.checkout_dirty`) and leaving it untouched when it has local changes. A Taste call (which takes neither) reads neither and runs in the Taste profile's directory, and a command that needs only the project or only the host checks only that one. |
| `events` | Imports the Cake Taste writer (rule below) and requires event schema 2. Section `events`: `{path}`. `decomp event append|tail|validate`; `tail` shows the schema 2 kind of every line. `RUNG` is an unknown kind everywhere (no reader map; old feeds are rewritten once outside the tool). |
| `stream` | Compositor, tile grid, transport, capture. A tile is a video role or a console. The browser page has no controls: the video is always fitted to the window (no scrollbars, no native-size mode) and audio starts as soon as the browser allows, on the first click or key anywhere. `stream.up.cursor = "hidden"` gives the compositor and its clients a transparent cursor theme so only the viewer's own cursor shows. The tile grid is any rectangle of at least two rows and two columns (2x2, 3x2, ...) in the seat `tiles.layout`; a role id repeated down one column is one tall tile, and a video role's `overlay_app_id` window floats exactly over its tile. |
| `console` | The one Textual console, which reads events as plain sentences (`console/human.py`: one sentence per operation, no raw kinds; expanding gives a Ran / Input / Expected / Actual / Result block, then the raw event). Boot tiles pin three status lines (`Passing`, `Stopped at`, `Next`) above the rows, and every tile's title ends in `checked Ns ago` with a 10 s re-read. The `activity` pane (`console.panes.activity`) is one chronological feed of the operation events with the lane as a tag, a function's whole trial history on expand, and a landing's Recipe proposal. A tile's `actors` lists kindless-event actors it also shows (e.g. build). one compact title line, no key footer; rows run oldest to newest, each with a live dim age column (`12s`, `4m`, `2h`), and every tile follows the bottom until the user scrolls up (End or the `↓ latest` control resumes). Panes read files and CLI JSON only: progress.json, `unbake report --next`, event feeds, run status, lane PULSE.json and transcripts. The `activity` footer counts the functions landed today from LAND messages that follow `decomp land`'s "Fix N ... stand-ins" convention and the `progress` file's function count and code percentage. |
| `tools deploy` | `decomp tools deploy --sha D [--unbake S] [--recipe S] [--taste S] --venv P...` installs `name @ git+URL@SHA` only (40-hex SHAs; wheels refused), after comparing decomp's pyproject pins, Recipe's unbake pin and the project pin file; any mismatch prints the pins that must move (`deploy.pin_must_move`) and installs nothing; then smoke tests `decomp dependencies` and `unbake symbols --version V`. `decomp unbake ...` results carry `cache` (unbake's per-stage hits and misses) and `decomp behave` timing carries `cache_hits` and `cache_misses`. |
| `make` | `decomp make [--project D] [--host F] ARGS...` runs the project's make as `unbake-run make -jN ARGS` in the tree (N from the seat's `land.jobs` admit command unless ARGS carry `-j`), streams its output to stderr and writes one MATCH (passed) or RUN-FAIL (failed) event with `payload.op = "build"`. It is the proof build a lane runs instead of raw make. |
| narration | Besides `unbake score|submit|land`, `decomp recipe next|work|try|skip|structure|name|apply|flags|style` writes a MATCH event (`payload.op = "recipe"`; apply is LAND, a failure RUN-FAIL) and `decomp unbake verify|check|audit|sync|setup` a MATCH or RUN-FAIL event (`payload.op = "unbake"`), all with the lane name, so every tool call of a lane shows on the stream. |
| `retarget` | `decomp land` carries each patch across the renames main made since the patch was cut: base = the newest commit matching the patch's pre-image blobs; renames = files git sees renamed plus symbols a `versions/*/symbol_addrs.txt` line renamed at the same address (a name the tree still defines is not a rename); the pre- and post-image of each patched file are rewritten (word-bounded identifiers, header includes, renamed paths) and the patch is cut again with real blobs so the 3-way merge stays valid. A patch naming nothing renamed is untouched; the lane row carries `retargeted {base, files, symbols}` and a non-blocking `land.retargeted` finding. |
| `lanes` | Launch, register, steer, end; the model ladder; the registry (the one list of lanes, which the orchestrator's peek reads: Codex lanes enter at launch, a Claude lane with `decomp lane register --name --transcript --kind --model`, and `lane end` closes both). A link that closes at its wall or cap writes its running ssh jobs (pids, hosts, remote pids, output files) to `JOBS.json` and HANDOFF.md, and `lane continue` opens the successor's brief with the ones still alive as "adopt, don't restart"; a link closing while such jobs run is continued without spending budget. Ladder values and the registry file are workspace configuration. Section `lanes`: `registry`, `ladder`, `codex`, `socket_dir`, `rules`. The test runner `ci/run_tests.py` (used by `ci/check`) gives every test a timeout, `ABU_TEST_TIMEOUT` seconds (default 90): a hang dumps every thread's stack and fails that test. Lane supervision (peek, recon, watchers) is the workspace's own hygiene and lives outside this repo. Only `launch`, `continue` and `end` write the registry. `continue --from OLD_DIR --name NEW` launches NEW beside OLD from OLD's brief (old `## Continuation` and rules dropped, one continuation pointing at OLD's HANDOFF.md and STATUS.md, rules appended), inheriting the spec from OLD's registry row or its unit's ExecStart, and refuses while OLD's unit is active (`--wait SECONDS` waits for it to close). `launch` also refuses (`lanes.tool_pin`) when the pin file of the lane's `--cwd` project names a tool version other than the installed one. The runner continues its own lane when it closes on an unfinished RESULT (`result` lanes end only on a `DONE` line in RESULT or RESULT.md) or a context handoff: a transient `relaunch-NEW` unit runs `continue --from OLD --name NEW` (trailing number plus one; `--continues` is the budget of links without progress: a link whose RESULT line names a pushed, committed or landed hex commit id, or whose owned git trees gained a commit since the link started, or whose declared `--export PATH` file (repeatable, absolute, under an `--owns` path, recorded in LAUNCH.json and inherited by `continue`) is newer than the link start with a hash other than at the link start, progressed and keeps the budget, any other link spends one, and a no-progress link at 0 gets a blocked LANE event saying "budget spent"; the event says progressed or spent), so the ladder and overlap guard apply, and every outcome is a LANE event. It needs `--profile`, which `launch` passes. |
| `supervisor` | Runs a target under gdb with retry and capture, the boot gate, RUN-FAIL events. Headless; the console reads its status file. Section `supervisor`: `{runtime_root, roles}`; `decomp supervisor run|status|show-artifact|viewer --role R`. A role's `env` and the stream's own `WAYLAND_DISPLAY`, `XDG_RUNTIME_DIR` and `PULSE_SERVER` reach the supervised process, so a seat can run it windowed (no `--headless`, `SDL_VIDEODRIVER=wayland`, `SDL_AUDIODRIVER=pulse`, `PULSE_SINK` the stream sink): its window floats over its video tile and, held by the debugger at a boot stop, keeps its last frame. `run` stops on SIGTERM; SIGHUP restarts the run, SIGUSR1 toggles the retry pause. RUN-FAIL goes to the seat `events` feed. While `run` lives its pid is in `<status_path>.pid`; a console tile whose sources name `supervisor_status` sends SIGHUP on F5 and SIGUSR1 on F7. |
| `build` | Committed-source build and verified releases (`build/SCHEMA.md`). Section `build`: the build tables plus `project_root`, `runtime_root`, `output_root`. `decomp build once [--prove-only]|status`. |
| `cycle` | `decomp cycle`: one blocking inotify loop over the section's source roots and refs (RefSource; a refs table's `pull_seconds` only runs `git pull --ff-only`). Each settled burst runs, each when configured: `build` (a fresh `decomp build ARGS`), `recipe`, `unbake report` with MATCH on the delta; `run_at_start` runs once first; `propose` runs the Recipe proposals on the files the landed commits changed and appends one LAND event with the summary (a `land_refs` commit then runs only this step); `land_refs` otherwise only appends LAND. A failed step is RUN-FAIL, and so is a ref repo whose `git pull --ff-only` fails (diverged, dirty, fetch error), once per reason with ahead/behind counts. |
| `proposals` | Recipe proposals after a landing, used by `land` and `cycle`: each step is `{name, args}` of a Recipe verb that only proposes (`structure`, `style`, `flags`, `look`, `status`, `name next|banners`); `{files}` expands to the landed sources. Nothing is applied (`recipe apply`, `recipe name submit` are refused in the profile), so no rename can invalidate a lane's pending patch; a failing step is a finding, never a failed landing. |
| `probe` | Oracle probe requests. Section `probe`: `{queue}`. `decomp probe request` writes `<queue>/requests/<id>.json` once and appends HANDOFF with `subject.address`; `serve` lists the open ones oldest first with the Taste repro `story` (its PROBE events carry `payload.request` = id); `status` joins requests to PROBE events: open, running, answered, superseded (a later request's `supersedes`). The console `experiments` pane (`{queue, limit}`) shows open requests with age, the last PROBE per owner address with match_state, and host counters. |
| `land` | `decomp land --tree T --base REF --patch LANE=PATH ...` applies lane patches (a function two patches both carry lands once: an identical change block is a no-op, a different body keeps the first and gives a non-blocking `land.duplicate_function` finding naming both lanes; symbol lines merge by name in union files, a symbol line a patch removes and the tree holds exactly is retracted first so a move or rename meets no stale line, and a conflicting address is a `land.symbol_conflict` finding with both values) (`--patch LANE=PATH[:MESSAGE]`; `git apply --3way --index`, in order; a conflicting patch lands per file: every file section that applies cleanly lands, each refused file is a blocking `land.file_refused` finding (git's reason) in the result and in the LAND event text, and a patch with no file landing is excluded whole; a function is credited only when all of the patch's files that name it landed, else `land.function_split`; files matching `land.union_paths` never conflict, their added lines merge as a line union) to a clean proof tree at REF, then checks each input against the state the earlier ones left, before any build, and refuses an input alone (the tree goes back to before it, a `land.patch_excluded` finding plus the reason's own: `land.symbol_conflict`, `land.symbol_invalid`, `land.symbol_clash` (splat reads the merged fact file whole and names both symbols at one address), `land.commit_subject`, `land.commit_hook`); then runs the gates and stops at the first failure: `unbake setup` (every round: it answers at once when nothing moved and re-extracts exactly the versions whose symbol facts, yaml or ROM changed), `unbake sync`, the configured check command with `-jN` from the configured admit command, `unbake sync` after check, `unbake sync --check`, then no marker line added in a file no patch touched, no untracked assembly file, no README code percentage below the base. unbake is called only through the pinned tool invoke (`unbake land` lands inbox submissions, a different job). The result lists per-gate pass, per-lane file groups (generated files join the last group) and function counts, a `commits` plan (one `{lane, files, functions, message}` per applied lane, in order; message is the explicit patch message or "Fix N <first marker> stand-ins in <top src dirs> by matching <names> as C", null with a non-blocking `land.commit_message` finding when a lane converted nothing and gave none) with ready `commit_commands` (`git add -- F && git commit -m M [-m BODY] -- F`) for the orchestrator to run, and one LAND event is appended. The generated subject is at most `land.subject_limit` characters (default 72, the commit-msg limit): when the full "Fix N ... by matching <names> as C" is longer it becomes "Fix N <marker> stand-ins in <dirs> by matching C", dirs trimmed to "A, B and N more dirs" or "N dirs", and the function list moves to the commit `body` (second `-m`). Every planned message is also checked against the tree's own commit-msg hook (git's hooks path) and the limit, so a violation is a blocking `land.commit_hook` or `land.commit_subject` finding; it refuses that input alone up front, and a message that breaks only as grouped for its commit fails the landing before anything is committed. A failing build gate (setup, sync, check, sync_after, sync_check) with more than one input landed is bisected by input: the tree is rebuilt with growing prefixes of the inputs (warm caches, at most ceil(log2 n) extra builds) until the first input whose presence breaks the build is found, that input is refused alone (`land.input_build_failed` with the build's reason, the result's `refused_inputs`) and the rest are built again; `attempts` lists every build and `cache` the unbake cache hits and misses of the run. It never commits or pushes. With `land.recipe` (steps of Recipe's proposal verbs, see `proposals`) it ends with a non-gating `recipe` gate that puts the pinned Recipe's names and structure suggestions for the landed source files in the result's `recipe` and the LAND event. Section `land`: `check` plus optional `jobs`, `union_paths` (fnmatch globs of append-only fact files such as `versions/*/symbol_addrs.txt`; pair with a `.gitattributes` `merge=union` line so plain git agrees), `markers`, `asm_suffix`, `readme`, `timeout_seconds`, `actor`, `recipe`, `recipe_suffixes`, `subject_limit`. |
| `behave` | `decomp behave --project TREE --host FILE --function SYM [--candidate FILE.c] [--version V] [--cases N] [--seed S] [--depth D]` runs the original function and a candidate C function on the same inputs and compares what they do; bytes (unbake) prove exactness, behaviour never replaces them. Both sides run through the one execution model of Cake Taste's recomp call probe (`taste repro probe --kind cases`): the original is recompiled from the ROM, the candidate is the object unbake's build context compiles (`tools.api_call` runs the one allowed `unbake.api` call, `build_context`, in the pinned interpreter), linked with the host's MIPS linker at a free address with every other symbol at its address in the version, and recompiled by N64Recomp next to the original symbols, so callees stay the original code and any difference is the C, not a host compiler. Siblings in the candidate's file that have an original address are pinned to it. Inputs are deterministic from `--seed`: the prototype (candidate file, then headers) gives the argument registers and stack words; a baseline, every argument swept alone over its edge values and pairwise combinations of a reduced set fill the `--cases` cap (default 48); pointer arguments point into seeded regions, a first short probe of the original shows which offsets it reads and (by fault tags) which fields and globals it dereferences, and those get regions of their own while its zeroed state globals are swept. Per case it compares the returned value the prototype makes meaningful, the net memory change (stack frame excluded), the ordered calls with the arguments their prototypes read, and callee-saved registers left changed; reads outside the seeded memory, calls to unprototyped functions and unknown return types are notes. Verdicts are `same`, `differs` (the first difference with the case inputs) and `untestable` (hardware access, an unmapped address, a timeout, a NaN check, a candidate that does not compile or link, with the reason); exit 0 for all three, the verdict is data. Without `--candidate` the result is `described`: per pointer argument the offsets read and written with widths, stored values and pointer fields, plus globals touched by symbol and the callees seen. Originals are cached by ROM digest, symbols, closure and cases. Learning rounds also tag the return value of every callee cut off at the boundary (a stub; a case's `stub_v0` makes the harness answer it per case): a fault at a tag plus a displacement means the original dereferenced that return value, and the stub then answers with a region of its own (null every fifth case) in the real run; fault tags are spaced a displacement apart, so a field a whole struct away is still named. A function without arguments is learned too (its globals and stubs). A case that writes more than 20000 call, stub or store events ends as fatal (a spin on a thread primitive), so a hung original costs one case, not a gigabyte of events. A probe that finds the repro lock held waits on it (the kernel lock, not a poll) and reports the seconds as `timing.lock_wait` (Cake Taste `lock_wait_seconds`). Optional profile section `behave`: `cases`, `depth`, `candidate_base`, `arena_base`, `region_bytes`, `timeout_seconds`, `learn_cases`, `learn_rounds`, `headers` (globs of prototype sources), `work` (cache and scratch root). Every comparison appends one PROBE event with `payload.op = "behave"` (`narrate.behave_event`: verdict same|differs|error, checks, differences, the first difference's inputs, expected and actual), which the activity pane shows. |
| `port` | Generates a port repository skeleton from a port spec (below). |
| `mcp` | The MCP shim (below). |

## Event schema 2

One JSON object per line. Schema 2 is additive over schema 1; every schema 1 line stays valid and is never rewritten.

```json
{"schema": 2, "time": "ISO-8601 with offset", "actor": "lane or tool", "status": "info|started|passed|failed|blocked|decision|handoff",
 "message": "one line of fact", "evidence": "path" | {"path": "...", "sha256": "64 hex"} | null,
 "kind": "RUN-FAIL|PROBE|MATCH|HANDOFF|LAND|LANE|DECISION",
 "subject": {"repo": "", "ref": "", "version": "", "function": "", "address": "0x..."},
 "lane": {"name": "", "kind": "tooling|impl", "model": "", "track": "official|experiment"},
 "payload": {}}
```

- `kind`, `subject`, `lane` and `payload` are optional. Schema 2 kinds are a closed set.
- Schema 1 kinds stay readable: readers show `PORT-FAIL`, `DECOMP` and `COMMIT` as `RUN-FAIL`, `MATCH` and `LAND`. Writers and kind filters accept schema 2 names only.
- The JSON Schema ships with the writer as `cake_taste/logs/event.schema.json`.
- Operation events: the `decomp` wrappers emit one event per operation themselves (module `narrate`), so every lane shows on the stream with no change to the lane. The kind stays in the closed set and `payload.op` says which operation: `MATCH` + `attempt` (one `unbake score`: function, version, size_bytes, attempt counted per function in `<feed>.attempts.json`, words {matched, target, built}, exact, score, variants, unit, first_difference, refusals, lane), `MATCH` + `submit` (one `unbake submit` row: function, exact, refused, landed_files, refusals), `LAND` + `landed` (`decomp land`: functions, gates, recipe proposals), and `PROBE` + `behave`, the schema `decomp behave` emits into with `narrate.behave_event`: `function`, `verdict` same|differs|error, `checks`, `differences`, `inputs`, `expected`, `actual`, `evidence`, `lane`. Cake Taste writes its own PROBE (`checks`, `differences`, `function`, `result`, `run_id`). `lane` is `DECOMP_LANE`, else the name of the directory that holds the project tree. Emitting never fails a command.
- Producers: Cake Taste instruments write PROBE and HANDOFF. decomp writes RUN-FAIL (supervisor), LANE (launch, steer, recycle, end), LAND (landed refs), MATCH (progress delta between two reports) and DECISION. Lanes append HANDOFF and DECISION through the public append command.

## One event writer

Cake Taste owns the only implementation of the event format and its flock append writer. decomp imports it (`cake_taste.logs.events` today) and MUST NOT write event lines itself. A second writer of the same format is a defect.

## Lane overlap guard

`decomp lane launch` refuses a lane when:

- any of its `owns` paths equals, contains or lies inside a live lane's `owns` path;
- it declares no owned paths, or a relative one;
- a lane of the same name is live, or its systemd unit is already active.

This is the one rule that keeps experiment work from interfering with the official decomp. There is no per-track flag; `track` is data the Lanes pane shows. The model ladder is checked at the same point: a lane's model must lie in its kind's range, and the top rung or any rung outside the range needs an owner override reason.

## Lane launch and the done marker

- `decomp lane launch|continue` validate every argument, the ladder, the tool pin and the overlap guard before writing anything. A refusal writes nothing: `continue` creates its new directory and `brief.md` only after every check passed, and removes them if the unit fails to start.
- A finished lane is declared by one marker: the first non-blank line of `RESULT` (or `RESULT.md`) is `DONE` (then end of line, a space or a colon). `RESULT: DONE`, `Status: COMPLETE`, a later `DONE` line or any other prose never ends a lane; the runner continues it. The text is printed into every continuation brief (`relaunch.DONE_RULE`).

## Port boilerplate

`decomp port new --spec SPEC DEST` writes a port repository into an empty directory: README in the tool README shape, LICENSE, CMake presets with warnings as errors, `src/platform` (the host boundary, the only code that may include OS or device headers), `src/boot` (the original boot chain; the first owner stops with `<subsystem>: original <label> owner <address> has no native implementation`), `tests/boot_gate.txt` with `cmake/boot_gate.cmake` (the executable must print every gate line in order and exit 1 at the stop), `ci/check`, and `port.json` (the spec: the port's project facts). The skeleton fixes the shape; the platform and game internals are the port's own work.

## MCP

`decomp mcp` is a stdio JSON-RPC shim whose code rarely changes.

- `tools/list` derives the tools from a fresh `decomp describe`: `decomp_run(args)` plus one `decomp_<command>(args)` per command group, each carrying the parser's own argument rows.
- `tools/call` runs the current CLI in a fresh interpreter, so edits to decomp take effect on the next call with no reinstall and no restart.
- After each call the shim re-derives the list; if it changed, it sends `notifications/tools/list_changed`.
- Only a change to `mcp.py` itself (the protocol handling) needs the client to restart the server.
